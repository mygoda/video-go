## 1. 设计基调

### 1.1 深色优先（dark-only for MVP）

**结论：MVP 只做深色，浅色在 token 里留位、不实现。**

三条理由，按权重：

1. **产物是图像和视频，界面不该跟内容争色。** 浅色界面的大面积白会压低相邻图片的观感亮度，用户判断不了"这张图到底够不够好"。深色是内容平台的默认解。
2. **同类工具全是深色**（liblib.art / Midjourney / Runway / 可灵）。用户是带着肌肉记忆过来的，浅色会让人觉得走错门。
3. **画布是长时间盯屏场景**，深色疲劳度低。

留位的成本几乎为零：颜色全部走 CSS 变量，浅色主题只是覆写 `[data-theme="light"]` 一段，组件代码零改动。**代价是那条规矩必须守住——任何组件里不许写死颜色值。**

### 1.2 三条原则

| 原则 | 具体含义 | 反例（我们不这么做） |
|---|---|---|
| **内容是主角** | 界面只用中性色 + 一个主色。产物缩略图静止时不叠任何 UI，hover 才出操作条 | 每张卡片常驻一排按钮、彩色标签满天飞 |
| **一屏一件事** | 生成器只有一个输入区；画布只有一块平面 + 一个对话面板 | 左侧参数面板 + 右侧结果区 + 底部时间轴的"专业软件"布局 |
| **状态必须可读** | 排队第几位、还要多久、为什么失败、扣没扣费，全部写在卡片上 | 一个转圈 + 一句"生成失败" |

### 1.3 视觉密度

芯片密集型工作台，但**只密在一处**：`ParamChipBar` 那一行。其余全部留白充足（section 间距 32–48px）。
理由：参数是高频操作，堆在一行里够得着；内容区密了就成了后台管理系统。

## 2. Design Tokens

权威定义见 [`ui/tokens.css`](./ui/tokens.css)。下面是速查与**为什么是这个值**。

### 2.1 中性色（背景靠亮度分层，不靠阴影）

| Token | 值 | 用在哪 |
|---|---|---|
| `--bg-sunken` | `#08080A` | 画布背景、输入框内陷 |
| `--bg-base` | `#0A0A0C` | 页面底色 |
| `--bg-surface` | `#131318` | 卡片、输入区、面板 |
| `--bg-elevated` | `#1B1B22` | Popover / Modal / Dock |

四层足够，**不要加第五层**。深色下相邻两层的亮度差必须 ≥ 3%，否则看不出边界；层数越多每层越挤。

浮层（Popover / Modal / Dock）除了背景更亮，还要 `inset 0 1px 0 rgba(255,255,255,.06)` 的顶部内高光——这是深色 UI 里"浮起来"的关键，比阴影管用，别省。

### 2.2 文字（含对比度校验）

对比度全部实测（WCAG 2.1 相对亮度公式），不是估的。**取最差场景**——同一个灰在 `--bg-elevated` 上比在 `--bg-base` 上更吃亏。

| Token | 值 | vs `bg-base` | vs `bg-surface` | vs `bg-elevated` | 判定 |
|---|---|---|---|---|---|
| `--text-primary` | `#F2F2F5` | 17.7:1 | 16.6:1 | 15.3:1 | AAA |
| `--text-secondary` | `#A0A0AB` | 7.6:1 | 7.2:1 | 6.6:1 | AAA |
| `--text-tertiary` | `#8A8A96` | 5.8:1 | 5.4:1 | **5.0:1** | AA |
| `--text-disabled` | `#4A4A54` | 2.3:1 | — | — | 不达标（有意） |

> 初稿的 `--text-tertiary` 是 `#7A7A87`，在浮层上只有 **4.0:1**，AA 不过。
> 它正好用在 `.popover-title` 和面板里的 `.hint` 上，是实打实的问题，已提亮。
> **教训：深色主题校对比度要按最亮的那层背景算，不能只看页面底色。**

`--text-disabled` 故意不达标：禁用态就该看着不可点。但因此有一条硬规矩——**禁用态旁边必须有一行达标的说明文字**（`.hint`，用 tertiary），告诉用户为什么不能点（"积分不足，还需 12 积分" / "该模型最多同时 2 个任务"）。禁用而不解释是最糟的交互。

### 2.3 主色与语义色

**主色拆成两个 token，这是必要的不是啰嗦：**

| Token | 值 | 角色 | 对比度 |
|---|---|---|---|
| `--accent` | `#7350F5` | **当底**：主按钮填充、选中 tab、进度条 | 白字压在上面 5.0:1（AA） |
| `--accent-text` | `#A992FF` | **当字**：链接、主色图标、选中项对勾 | 最差场景 6.7:1（AAA） |

原因：同一个紫做不到两头都合格。够暗才压得住白字，够亮才能在深底上当文字。
初稿只有一个 `#7C5CFF`，白字压上去 **4.3:1**，正文 AA（4.5）差一点——按钮上写着「生成」两个字，这是最不该将就的地方。
`--accent-hover: #7B5AF8` 白字 4.51:1，是"能再亮的上限"，**不要再往上调**。

| Token | 值 | 语义 | vs surface |
|---|---|---|---|
| `--credit` | `#FFB340` | **积分专用**。钱有独立识别色 | 10.4:1 |
| `--success` | `#3DD68C` | 完成、退费 | 9.9:1 |
| `--warning` | `#F5A524` | `upstream_rate_limited` | 9.1:1 |
| `--danger` | `#F5556E` | `invalid_param` | 5.6:1 |
| `--muted` | `#8A8A96` | `content_rejected` / `canceled` | 5.4:1 |

三条约定：

- **主色只出现在"可操作"的地方**，不用来装饰。整个工作台里主色的总面积应该很小——一个生成按钮、一个选中框。唯一例外是登录页的品牌渐变。
- **积分色和 warning 分开。** 都用橙会让"余额"和"出错了"长得一样。
- **语义色三个来源与 `TaskErrorCode` 一一绑定**，见 §5.2。改颜色等于改语义，不要随手换。

`--muted` 和 `--text-tertiary` 取值相同（`#8A8A96`），这是有意的：一个灰，两种语义，各自命名。**不要把其中一个写成另一个的别名**——将来 `--muted` 要变，不该连带把所有次要文字一起改了。

### 2.4 字体

- 中英混排走系统字体栈（`--font-sans`），**不引入 web font**。首屏不该为字体等一次网络请求，且中文字体包体积以 MB 计。
- **数字一律 `--font-mono` + `tabular-nums`**：积分余额、seed、耗时、revision、进度百分比。理由很实际——积分从 `1,240` 变 `1,224` 时，比例字体会让整行宽度跳动，等宽不会。
- 字号档 `11 / 12 / 13 / 14 / 15 / 20 / 24 / 32`。**界面正文默认 13px**（中文在 13px 下比英文更耐读，14px 会显得松散）；prompt 输入框用 15px——主输入比周围大一档，是"这里是你要打字的地方"的无声提示。
- 字重上限 600。深色背景上 700 的中文会糊成一团。

### 2.5 间距 / 圆角 / 高度

- 间距 4px 基数。组件内 `4/8/12`，组件间 `16/24`，区块间 `32/48`。
- 圆角：芯片和徽章 `full`；按钮和上传位 `10px`；卡片和 Popover `14px`；Composer / Modal / Dock `18px`。**规律是"越大的容器圆角越大"**，混着用会显得廉价。
- 高度定死（`--h-chip: 32` / `--h-btn: 36` / `--h-btn-lg: 40` / `--h-input: 40` / `--h-topbar: 56`）。同类控件不许自定义高度——这是界面显得整齐的唯一来源。

### 2.6 接进 Tailwind

`frontend-design.md §0` 选的是 Tailwind + CSS 变量。接法：

```js
// tailwind.config.js —— 只映射，不重新定义
theme: {
  extend: {
    colors: {
      bg:     { sunken:'var(--bg-sunken)', base:'var(--bg-base)',
                surface:'var(--bg-surface)', elevated:'var(--bg-elevated)',
                disabled:'var(--bg-disabled)' },
      fg:     { DEFAULT:'var(--text-primary)', secondary:'var(--text-secondary)',
                tertiary:'var(--text-tertiary)', disabled:'var(--text-disabled)' },
      accent: { DEFAULT:'var(--accent)', hover:'var(--accent-hover)',
                text:'var(--accent-text)', subtle:'var(--accent-subtle)' },
      credit:'var(--credit)', success:'var(--success)',
      warning:'var(--warning)', danger:'var(--danger)', muted:'var(--muted)',
    },
    borderRadius: { md:'var(--radius-md)', lg:'var(--radius-lg)', xl:'var(--radius-xl)' },
    transitionTimingFunction: { DEFAULT:'var(--ease)' },
  }
}
```

**规矩：`src/` 下不允许出现十六进制颜色值。** 加一条 ESLint / CI grep 检查，和 §3.6 那条"不许出现模型 id"并列。理由一样——破防的代价是后面每加一个主题都要全量重扫组件。

## 3. 组件视觉规范

尺寸以 [`ui/mockup.css`](./ui/mockup.css) 为准，下面只列**容易做错的地方**。

### 3.1 参数芯片（`ParamChip`）

界面里出现频率最高的东西，也是最能看出糙细的东西。

```
┌──────────────────────┐
│  重绘强度  0.6  ▾    │   高 32 · 左右 padding 12 · 圆角 full · 字号 12
└──────────────────────┘
   ↑secondary ↑primary
```

- **参数名用 `--text-secondary`，参数值用 `--text-primary` + 500 字重。** 值比名重要，靠颜色和字重分主次，不靠字号——字号一变行高就乱。
- 四个状态各有专属边框色：静止 `--border-default` / hover `--border-strong` / **展开 `--accent` + `--accent-subtle` 底** / 错误 `--danger` + `--danger-bg` 底。
- 第五个状态是 **`.migrated`**（切模型导致参数回落，`--warning` 边框高亮 1.5s 后淡出）。对应 `frontend-design.md §2.4` 的"让用户知道哪些被改了"。**这个状态很容易在实现时被忘掉**，它是唯一一个由系统而非用户触发的芯片状态。
- `aspect_select` 的芯片上要画一个按真实比例的迷你线框（`.ratio-box`），16:9 就是扁的，9:16 就是竖的。**光看 "16:9" 四个字不如看一眼形状快**，展开态的网格同理。
- 禁用（`enabled_when` 不满足）是 `opacity .5` + 保留内容 + `disabled_hint`，**不是隐藏**。隐藏会让用户以为这个模型没这功能。

### 3.2 PromptComposer

- 宽 768（`--w-composer`），居中。整块 `--bg-surface` + 圆角 18。
- **`:focus-within` 时整个容器亮起来**（边框转 `--accent-border` + 3px 外扩 `--accent-subtle`），而不只是 textarea 描边。这让"上传位 + 输入框 + 芯片栏"被读成一个输入单元，而不是三个控件。
- 内部一条 1px 分隔线把输入区和芯片栏分开。芯片栏固定高 56。
- 右下角固定顺序：**费用估算 → 生成按钮**。费用在左，因为用户按下去之前最后看的应该是价格。
- 芯片一行放不下时，**溢出的进 `⚙`，不换行、不横向滚动**。换行会让容器高度跳变；横向滚动会让参数藏起来还没提示。

### 3.3 任务卡片（`TaskCard`）

- 图片任务 `aspect-ratio: 1/1`，视频任务 `16/9`。网格 `repeat(auto-fill, minmax(200px, 1fr))`。
- `succeeded`：**静止时只有画面**，hover 才浮出底部渐变 + 操作条（下载 / 做同款 / 送入画布 / 删除）。删除单独推到右端，避免误触。
- `queued` / `running`：不放假图。`running` 用 shimmer 骨架 + 进度条；`queued` 用一个静态图标 + 队列位置。**两者视觉必须区分明显**——都转圈的话用户分不清"在排队"和"在生成"，而这两件事的等待预期差一个数量级。
- 进度条 3px，`--accent`。超过 `eta.p90` 停在 90% 并把副标题换成"仍在生成中，该模型偶尔较慢"（见 [generator-video.html](./ui/generator-video.html)）。

### 3.4 画布卡片

| 状态 | 视觉 |
|---|---|
| 普通 | `--bg-surface` + `--border-subtle` + 圆角 14 |
| **选中** | `--accent` 描边 + `0 0 24px var(--accent-glow)` 外发光 |
| **来源（血缘）** | `--accent-border` **虚线** + 3px `--accent-subtle` 外扩 |
| 其余（有选中时） | `opacity: .35` |

三级对比是必需的：选中 → 来源 → 背景。只做两级的话，"这张图是从哪来的"这个信息就丢了，而它是不做连线编排的前提（`frontend-design.md §5.4`）。

**虚线必须比 `--border-subtle` 明显一个量级**，否则在深色底上等于没画——这一条是照着渲染出来的稿子改的，第一版虚线看不见。

卡片工具条（`↻ ⊹ ⋯`）浮在卡片**上方 32px**，属于**覆盖层**而不是卡片的子节点。原因很硬：卡片必须 `overflow:hidden` 才能让媒体吃到圆角，子节点会被裁掉。这正好印证了 `frontend-design.md §5.5` 说的"卡片层与覆盖层是两个兄弟 DOM 层"。

### 3.5 按钮

四档：`btn-primary`（主色实底）/ `btn`（描边）/ `btn-ghost`（无边框）/ `icon-btn`（28×28 方形）。
**一屏内 `btn-primary` 只允许出现一次。** 生成器上是「生成」，登录页上是「登录」，画布上是对话的发送键。

禁用态统一 `--bg-disabled` 底 + `--text-disabled` 字，且必须配 `.hint` 说明理由（见 §2.2）。

### 3.6 动效

三档，超出请说明理由：`120ms`（hover、芯片值变化）/ `180ms`（Popover 展开、卡片入场）/ `240ms`（Modal、Dock 折叠）。缓动统一 `cubic-bezier(.2,0,0,1)`。

只有两处允许持续动画：骨架屏 shimmer（1400ms）和进度条推进。**其余一律不许有常驻动画**——画布上同屏几十张卡片，任何常驻动画都会变成噪音和电池杀手。

`prefers-reduced-motion` 下把三档时长全设 0（**关掉，不是缩短**），但骨架屏和进度条保留——那是状态指示，不是装饰。

## 4. 页面视觉

每页都有可打开的稿子，下面只写结论。

### 4.1 生成器 · 图片 → [`ui/generator.html`](./ui/generator.html)

```
       ┌── 图片 ──┬── 视频 ──┐          ← tab 居中，走路由
  ┌────────────────────────────────┐
  │ [参考图][+]  参考图 · 最多 4 张  │   ← 传了 = 图生图，前端不发 mode
  │ 深夜便利店的收银台，冷白色灯管… │
  ├────────────────────────────────┤
  │ ⬤Seedream 风格▾ ▭16:9·2张▾      │
  │ 重绘强度 0.6▾ ⚙   ⚡16·约15s [生成]│
  └────────────────────────────────┘
  今天 ──────────────────────────────
  [生成中] [排队中] [产物] [产物] [✕参数] [↻限流] [⃠审核]
```

- 「重绘强度」这颗芯片是**声明式出现的**（`visible_when: has_input`），稿子里画上它是为了让人看见"传图前后界面会变"这件事。
- 展开态画的是 `compound`（比例 + 数量合一个 Popover），因为它是最复杂的一种控件；其余七种控件的展开态是它的简化版。

### 4.2 生成器 · 视频 → [`ui/generator-video.html`](./ui/generator-video.html)

**故意做成和图片 tab 逐像素一致。** 变的只有 schema 给的东西：上传位标签（参考图 → 首帧）、芯片内容、费用、eta。
这张稿子的作用是**证明** `frontend-design.md §3` 那条验收线在视觉上成立——如果两个 tab 需要不同的布局，说明 schema 抽象漏了东西。

### 4.3 画布 → [`ui/canvas.html`](./ui/canvas.html)

- 顶栏压到 44px（比 AppLayout 的 56 更窄），无侧边栏。画布要视口。
- 背景点阵 24px，`rgba(255,255,255,.07)`。**这是无限平面上唯一的空间参照**，缩放时随 `k` 变——没有它，用户拖动时不知道自己在动。
- 对话面板 360px 宽，右下角，`backdrop-filter: blur(16px)`。**必须半透明**：它盖住的是画布，用户要能感觉到下面还有内容。
- 稿子里同时画了：选中态、血缘虚线、弱化态、生成中卡片（原位骨架，位置尺寸不变 = 锚点锁定）、版本切换器 `‹ 2/3 ›`、引用 chip 区。这几个是画布交互的全部视觉词汇，没有第七个。

### 4.4 资产库 → [`ui/assets.html`](./ui/assets.html)

**瀑布流（CSS `columns`），不是等高网格。** 产物比例从 21:9 到 9:16 都有，等高网格会大面积裁切，而资产库的唯一用途就是"找到那张图"。
静止时只有画面，hover 才出 prompt 和模型名。

### 4.5 个人中心 → [`ui/me.html`](./ui/me.html)

只有三件事：积分、存储配额、改密码。**没有充值入口**——平台统一持有 Key 不接支付是已定前提，放一个灰掉的"充值"按钮只会让人一直问。
积分数字用 mono，`--credit` 色。

### 4.6 登录 → [`ui/login.html`](./ui/login.html)

`bare` 布局，无顶栏。**唯一允许大面积主色渐变的页面**（两团 radial-gradient），工作台内不这么做。
错误贴在表单下方而不是 toast——登录失败要留在原地可读、可改。

### 4.7 未登录营销页

MVP 不做，稿子也不出。`frontend-design.md §1.1` 已经为它留了 `MarketingLayout` 的位置。**现在画等于浪费**：营销页的视觉取决于届时有什么案例作品，现在没有。

## 5. 状态设计

### 5.1 空 / 加载

| 场景 | 呈现 |
|---|---|
| 结果流为空（新用户） | 居中插画位 + "写一句话，开始第一次生成" + 一个指向输入框的箭头 |
| 资产库为空 | "还没有产物" + 「去生成」按钮 |
| 画布为空 | 点阵背景 + 居中提示"在下方对话框描述你的短剧" |
| 列表加载中 | **骨架屏，不是 spinner**。骨架要长得像最终内容（卡片形状 + 圆角一致） |
| 首屏路由加载 | 顶部 2px 主色进度条，不遮内容 |

空状态一律**给一个明确的下一步动作**，不只是说"暂无数据"。

### 5.2 失败三分类的视觉（与 `TaskErrorCode` 硬绑定）

| code | 图标底 | 主色 | 操作 |
|---|---|---|---|
| `invalid_param` | `--danger-bg` | `--danger` `!` | 「修正并重试」 |
| `upstream_rate_limited` | `--warning-bg` | `--warning` `↻` + 进度条 | **无按钮**（后端在退避重试） |
| `content_rejected` | `--muted-bg` | `--muted` `⃠` | 「修改提示词」 |
| `insufficient_credit` | `--muted-bg` | `--muted` `⚡` | 「去个人中心」 |
| `internal_error` / 未知 | `--muted-bg` | `--muted` `⚠` | 「重试」 |

**颜色不是唯一信息载体**：每一类都有专属图标 + 独立文案 + 不同的操作按钮，色盲用户靠后三者也能区分。右下角固定标注「未扣费」（读 `error.charged`，不写死）。

### 5.3 Toast

只用于**与当前视线无关**的事：画布保存失败、SSE 断线降级为轮询、下载完成。
**表单校验和任务失败不用 toast** ——它们有明确的归属位置（芯片下方 / 任务卡片上），toast 会让用户看完就找不着了。
右下角，宽 320，4s 自动消失，可手动关。

## 6. 图标

**结论：MVP 用手工维护的内联 SVG（`src/shared/ui/icons.tsx`，约 24 个），不引入图标库。**

理由：`lucide-react` 之类虽然 tree-shakeable，但仍是一条新依赖，而 CLAUDE.md 要求新依赖需 issue 显式批准。24 个图标手写 SVG 约 150 行，成本低于走审批。
**如果后续同意引入，推荐 `lucide-react`**（线性、1.5px 描边、24 网格，和这套视觉的克制程度匹配）—— 需要在本 issue 下明确批准后再动。

规范：线性图标，描边 1.5px，尺寸 16（芯片内）/ 18（按钮内）/ 20（顶栏）。`currentColor` 取色，**不给图标单独指定颜色**。

> 稿子里用的是 emoji（🖼 📝 🎬 ⚡ ⚙）作为占位，**实现时全部替换成 SVG**。emoji 在不同系统上长相不一致，不能进产品。

## 7. 响应式

**桌面优先，且明确划死边界：**

| 断点 | 行为 |
|---|---|
| ≥ 1280 | 完整体验，画布可用 |
| 1024 – 1279 | 生成器 / 资产库正常；画布可用但对话面板改为可折叠 |
| 640 – 1023 | 生成器单栏天然成立，芯片栏**横向滚动**；资产库降到 2 列；**画布显示"请用更大的屏幕打开"** |
| < 640 | 只保证登录和生成器可用（芯片进 `⚙`），画布与资产库给提示页 |

**画布不做移动端。** 无限平面 + 多选 + 拖拽在触屏上是另一套交互（手势冲突、无 hover、没有右键），不是把布局压窄能解决的。硬做会同时毁掉两端。这是取舍，不是偷懒。

## 8. 可访问性（视觉侧）

`frontend-design.md §8` 定了语义和键盘，这里补视觉部分：

- **焦点环全局统一**：`0 0 0 2px var(--bg-base), 0 0 0 4px var(--accent)`，双环保证在任何背景上都可见。不允许组件自定义，更不允许 `outline: none` 了事。
- 正文文字对比度全部 ≥ 4.5:1（校验表见 §2.2）。
- 信息不单靠颜色：失败三分类 = 颜色 + 图标 + 文案 + 操作（§5.2）；选中态 = 描边 + 发光 + 其余弱化。
- 点击热区 ≥ 28×28。芯片高 32 达标；`icon-btn` 28 是下限，不要再小。
- `prefers-reduced-motion` 见 §3.6。

## 10. 需要拍板的三件事

写稿时定了，但属于主观取舍，**如果不认同请在 issue 下说，改起来只动 `tokens.css`**：

1. **主色定紫（`--accent: #7350F5` 当底 / `--accent-text: #A992FF` 当字）。** AIGC 工具的常见选择，和产物（多为写实/电影感画面）不容易撞色。备选是青蓝，更冷静但和视频类产物撞得多。**换色只能整组换**——底色和文字色是配套算出来的，单改一个会破对比度（见 §2.3）。
2. **深色 only，浅色不实现。** 见 §1.1。留了 token 位，后补成本低。
3. **图标不引入依赖，手写 24 个 SVG。** 见 §6。若同意引 `lucide-react`，说一声即可。
